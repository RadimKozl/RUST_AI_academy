# ReAct Scientific Agent (`gfrig_react_scientific_agent`)

A high-performance, explainable (XAI) ReAct-style scientific agent built in Rust using **`rig-core` (v0.46)**, native **Ollama** integration, and a custom graph-flow orchestration state machine.

The agent executes rigorous scientific literature searches (via the arXiv API) and precise symbolic math calculations (via a custom zero-dependency polynomial algebra engine and `mathcore`), providing full audit trails and LLM-generated decision rationales for every tool invocation.

---

## 🚀 Key Features

* **Rig-Core Orchestration (`v0.46`)**: Leverages modern agentic primitives (`AgentBuilder`), type-safe `Tool` trait implementations, and multi-turn ReAct completion loops.
* **Native Local LLM Execution**: Connects directly to a local **Ollama** daemon (`http://localhost:11434`) via `OllamaConfig` without API key workarounds or environment variable mutations.
* **Explainable AI (XAI) Telemetry**: Thread-safe telemetry (`XaiTracker`) captures graph node transitions, execution durations in milliseconds, raw inputs/outputs, and explicit `rationale` explanations generated by the LLM prior to every tool call.
* **Structured JSON Audit Reports**: Serializes a complete `XaiReport` containing the execution trace, reasoning summary, and final answer for compliance and debugging.
* **Hybrid Symbolic Math Engine**: Combines a custom recursive-descent polynomial parser/evaluator (`poly.rs`) with `mathcore` CAS for symbolic differentiation and root solving.

## 🏃 Usage

Run the default scientific workflow (*"Find recent papers on quantum error correction and evaluate polynomial x^2 + 4*x + 4"*):

```bash
cargo run
```

### Output Sections
1. **Graph Execution Logs**: Real-time stdout markers indicating graph node transitions (`InitState` $\rightarrow$ `ReActAgentLoop` $\rightarrow$ `FinishGraph`).
2. **Final Graph Output**: Markdown-formatted response split into `### Reasoning Trace` and `### Final Answer`.
3. **XAI Audit Report (JSON)**: Pretty-printed `XaiReport` JSON object detailing every visited node, tool call latency, arguments, raw tool responses, and decision rationales.

## 🧠 Detailed Module & Code Architecture

### 1. `src/lib.rs` — Crate Root & Public API
Declares the internal modules (`graph`, `poly`, `tools`, `xai`) and re-exports the primary workflow types (`ScientificGraphWorkflow`, `GraphState`) and telemetry types (`XaiReport`, `XaiTracker`) so both the binary crate (`main.rs`) and integration tests (`tests/`) share a clean public interface.

### 2. `src/main.rs` — CLI Entry Point
Initializes the Tokio async runtime (`#[tokio::main]`), instantiates `ScientificGraphWorkflow` with a multi-domain scientific query, executes `.run().await`, and prints both the human-readable Markdown output and the serialized `serde_json::to_string_pretty` XAI audit report.

### 3. `src/graph.rs` — Graph-Flow State Machine & Agent Orchestration
* **`GraphState`**: Holds the `input_query`, sequential `execution_trace` node names, `final_output` string, and the compiled `Option<XaiReport>`.
* **`ScientificGraphWorkflow`**: Manages the deterministic graph lifecycle:
  1. **`InitState`**: Initializes the `XaiTracker` and records the starting node.
  2. **`ReActAgentLoop`**: Instantiates the native `OllamaConfig::new().client()` targeting `qwen3.5:9b`, registers `ArxivTool` and `SymbolicaTool` with cloned `XaiTracker` handles, and enforces a strict preamble requiring the LLM to populate `rationale` fields and separate its output into `Reasoning Trace` and `Final Answer`. Executes up to `.max_turns(5)`.
  3. **`FinishGraph`**: Parses the model's response into reasoning and answer segments and compiles the final `XaiReport`.

### 4. `src/tools.rs` — Instrumented Rig Tools
Defines custom error handling (`ToolError` via `thiserror`) and implements the `rig::tool::Tool` trait (`NAME`, `description`, `parameters`, `call(&self, &mut ToolContext, args)`):
* **`ArxivTool` (`search_arxiv`)**: Accepts `ArxivArgs { rationale, query }`. Encodes query terms into arXiv API boolean `AND` clauses (`sortBy=submittedDate`), fetches the 5 newest entries via `reqwest`, parses XML with `roxmltree`, and logs execution latency and results to `XaiTracker`.
* **`SymbolicaTool` (`symbolica_calculate`)**: Accepts `SymbolicaArgs { rationale, expression }`. Combines `poly::parse` / `poly::format_poly` for exact polynomial expansion with `MathCore::differentiate` and `MathCore::solve` for symbolic derivatives and root finding, recording full telemetry in `XaiTracker`.

### 5. `src/poly.rs` — Univariate Polynomial Algebra Engine
A self-contained, zero-dependency recursive-descent parser and algebraic evaluator for polynomials in a single variable $x$ (up to degree 64):
* **Parser (`Parser`)**: Supports `+`, `-`, `*`, `/` (by non-zero constants), `^` / `**` (non-negative integer exponents), parentheses, unary signs, and implicit multiplication (e.g., `4x`, `2(x+1)(x-1)`).
* **Algebraic Operations**: Implements polynomial addition/subtraction (`add`), convolution multiplication (`mul`), power-rule differentiation (`derivative`), Horner's method evaluation (`evaluate`), canonical string formatting (`format_poly`), and analytical root solving up to quadratic degree (`roots_text`).

### 6. `src/xai.rs` — Explainable AI Telemetry & Audit Reporting
Provides thread-safe observability across asynchronous tool executions:
* **`XaiTracker`**: Wraps `Arc<Mutex<XaiTrackerState>>` so concurrent or sequential tool calls can safely append telemetry without lifetime conflicts.
* **`NodeTrace` & `ToolExecutionRecord`**: Captures step indices, UTC timestamps, tool names, LLM-provided `decision_rationale`, JSON-serialized `input_arguments`, `raw_output`, `execution_time_ms`, and `SUCCESS`/`ERROR` status.
* **`XaiReport`**: Top-level serializable audit structure containing total workflow wall-clock duration (`total_duration_ms`) and synthesized reasoning summaries.

### 7. `tests/integration_test.rs` — Verification Suite
* `test_graph_state_initialization`: Verifies clean initial state creation.
* `test_symbolica_tool_execution`: Tests `SymbolicaTool` directly with `ToolContext::new()` and asserts that `XaiTracker` accurately records the tool name and `decision_rationale`.
* `test_full_scientific_workflow`: End-to-end workflow test marked `#[ignore = "requires running Ollama"]` for CI/CD safety.
